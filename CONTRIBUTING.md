# Contributing

1. Create a focused branch from `main`.
2. Do not commit credentials, production data, or environment files.
3. Keep backend behavior covered by tests where practical.
4. Run `python -m compileall backend` and `yarn build` before opening a pull request.
5. Explain security, database, or payroll-calculation changes clearly in the pull request.

Use fictional data in examples and tests. Never include real employee schedules or salary records.
